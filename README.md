# LiveHealthy: Know Your Disease

Third app in the LiveHealthy suite (after LiveHealthy: Medicine Reminder and LiveHealthy: Vitals).
A bilingual (Urdu / English) Android app that teaches the basic facts about common chronic
diseases in plain language, with a trusted reference behind every fact. It is health
**education** only: no diagnosis, no symptom checker, no treatment advice.
Scope: [docs/design-v1.md](docs/design-v1.md) (written as "LiveHealthy Learn", renamed Know Your Disease).

- **V1 topics:** high blood pressure; diabetes (prediabetes, type 2, gestational) as one group;
  obesity. Each topic has the same seven parts (§3).
- **Stack:** Flutter 3.41 / Dart 3.11, provider, gen-l10n (EN + UR, RTL), flutter_svg, Noto
  Nastaliq Urdu (bundled), Cloud Firestore (content updates only), Crashlytics (crash reports only).
- **No login, no user data, no analytics.** Permissions: INTERNET only (plus Firebase's
  ACCESS_NETWORK_STATE).
- **Firebase project:** `livehealthy-kyd`, its own project and deliberately *not* the shared
  `live-healthy-medreminder` patient-data project (D3). Android app id `com.homilabs.livehealthy_kyd`.
- **Repo:** github.com/AwaizFatima08/LiveHealthy-KYD · **Site:** https://livehealthy.homilabs.org/

## Layout
```
app/                 Flutter app
  lib/core/content/  content model + validation (pure Dart)
  lib/services/      content_repository (bundled + downloaded), update_service, tool_launcher
  lib/screens/       onboarding, home, group, disease, section, references, settings
  assets/content/    bundled JSON: GENERATED by scripts/publish_content.py, never hand-edited
  assets/graphics/   language-free SVGs: GENERATED by scripts/make_graphics.py
  test/              unit, service (fake Firestore) and widget tests (incl. small-screen/large-font)
  integration_test/  on-device end-to-end journey
content/             ★ SOURCE OF TRUTH: one JSON per topic, references.json, manifest_source.json
firebase/            firestore.rules + rules tests
store/               Play listing text + graphics
scripts/             publish_content.py (+ tests), make_graphics.py, make_icons.py,
                     make_screenshots.py, run_e2e.sh, backup.sh
secrets/             release keystore + Firebase admin key (gitignored; never commit)
```

## Everyday commands
```bash
python3 scripts/publish_content.py                    # validate content (dry run)
python3 scripts/publish_content.py --write            # bump versions, regenerate app/assets/content/
scripts/.venv/bin/python scripts/publish_content.py --publish   # + upload to Firestore (needs admin key)
python3 -m unittest scripts/test_publish_content.py   # validator tests
cd app && flutter analyze && flutter test             # Dart tests
cd firebase/tests && npm install && npm test          # rules tests (JDK 21+)
firebase emulators:start --only firestore             # (repo root, JDK 21+), then:
scripts/run_e2e.sh <device-id>                        # on-device end-to-end against the emulator
cd app && flutter build appbundle --release           # Play upload
scripts/backup.sh                                     # local + Google Drive backup
```
The Firestore emulator uses port **8086** (8085 is used by the Vitals/Medicine Reminder emulator).
One-time setup for publishing: `python3 -m venv scripts/.venv && scripts/.venv/bin/pip install firebase-admin`.

## Changing content (the normal workflow)
1. Edit `content/<topic>.json` (both languages) and, for a new source, `content/references.json`.
2. `python3 scripts/publish_content.py`. It refuses anything unsafe: a missing language, a
   section with no reference, an unresolved [n], a missing graphic, or a key number that doesn't
   match Vitals' `reference_ranges.dart` exactly (gestational content is exempt).
3. `scripts/.venv/bin/python scripts/publish_content.py --publish`. Changed topics get a new
   version. Phones pick it up within a day, and keep working offline with the copy they have.
4. Commit (the bundled copy in `app/assets/content/` changes too, so the next app release ships it).

New **graphics** need an app update (they're bundled). Unknown block types in newer content are
skipped by older apps, and `minAppVersion` in `manifest_source.json` protects old versions.

"Track it" buttons are switched remotely: `toolLinks` in `manifest_source.json`
(`live` / `comingSoon` / `hidden`). An app that's installed always shows **Open**.

## Website
livehealthy.homilabs.org is the shared site for the whole family. One privacy policy and one set
of terms cover every app, each with a Know Your Disease section. The source is in the Medicine
Reminder repo (`live_healthy/website/`); it's hosted on Hostinger and uploaded by hand to the site
root. Links are in `app/lib/core/constants/links.dart`.
